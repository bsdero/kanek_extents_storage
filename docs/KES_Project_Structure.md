## Standing note (Phase 6 docs truth pass)

This document previously described a large, multi-directory project
layout (`src/core/`, `src/flash/`, `src/zones/`, `src/serialization/`,
`src/platforms/{linux,android,macos,embedded}/`, `src/profiles/`,
`tools/kes-mkfs`/`kes-info`/`kes-fsck`/`kes-defrag`/`kes-benchmark`/
`kes-simulator`/`kes-tune`, a profile-driven build system with
per-hardware `.mk` files, and a matching CI matrix) with dozens of
source files that do not exist anywhere in this repository. This
revision is a full rewrite reflecting the actual, much smaller
project: three source files (~1600 lines total) plus their headers, a
flat root `Makefile`, and a `tests/`/`examples/`/`docs/` layout with
no subdirectories. See `AGENTS.md`'s "Repository Layout" and "Module
layering" sections, which this document now matches.

## The Real Build System

The entire build system is one root `Makefile`. There is no
`PROFILE=`, `MEMORY_BUDGET=`, or `FEATURES=` variable, no per-platform
`.mk` include files, and no auto-detection of hardware. Every build
command runs from the repository root (unlike sibling project KFL,
which builds from a `src/` subdirectory):

```bash
make all          # build build/libkes.a + build/libkes.so.1.0.0
make test-core    # build + run test_kes_minimal only
make test         # build + run all 6 test binaries
make debug        # DEBUG=1: -g3 -O0 -DDEBUG build
make examples     # build examples/example_kes_usage.c
make run-example  # build and run examples/example_kes_usage.c
make clean        # remove build/, stray /tmp test-binary copies
make install      # copy to /usr/local/{lib,include/kes} (sudo)
make info         # print resolved build config
make help         # list all targets
make asan         # clean rebuild + run tests under ASan+UBSan
make tsan         # clean rebuild + run tests under TSan
make valgrind     # clean rebuild + run tests under Valgrind
make sanitize-all # asan + tsan, then a plain rebuild
make check-all    # normal + asan + tsan + valgrind, gated on all passing
```

Build flags are fixed, not profile-selected: `-std=c99 -Wall -Wextra
-Werror -fPIC`, `-O2 -DNDEBUG` by default (`-Werror` means any new
compiler warning fails the build). `TEST_SOURCES =
$(wildcard tests/test_*.c)` (`Makefile:57`) means a new
`tests/test_*.c` file is picked up automatically without editing the
Makefile, as long as it follows the existing test-table/`main()`
pattern used by the other files in `tests/`.

`make all`/`make asan`/`make tsan` first run `foundations-fetch`,
which clones the sibling `kanek_foundations` (KFL) repo to
`../kanek_foundations` if it isn't already checked out there --
`-I../kanek_foundations/src` is on the include path so `trace.h` is
reachable. Nothing in `src/` links `libkfl.a`; the dependency is
header-only, for `TRACE_ERR`/`TRACE_SYSERR`/`TRACE_ERRNO` macros. See
`AGENTS.md`'s "Building and Testing" section for the complete,
authoritative list -- this section is kept intentionally short to
avoid the two documents drifting apart again.

## Testing Infrastructure

There is no `tests/unit/`, `tests/integration/`, `tests/performance/`,
`tests/flash_simulation/`, or `tests/regression/` subdirectory --
every test file lives flat in `tests/`, and each maps 1:1 to one
binary under `build/tests/`. There is no per-test filtering flag, and
no shared `tests/common/test_framework.c` -- each test file defines
its own small `TEST_ASSERT`/`TEST_SUCCESS`-style macros and a
`{name, fn}` table (see any file in `tests/` for the shape). `test`
and `test-core` both copy the built binary to `/tmp` before executing
it -- existing, intentional Makefile behavior, not something to
remove; `make clean` removes those `/tmp` copies too.

See `TESTS_AND_EXAMPLES.md` for what each of the six test binaries
covers and the current pass/fail baseline.

## Documentation Generation

There is no `doxygen`/`pandoc`-based documentation build, no
`scripts/utilities/documentation_build.sh`, and no generated
`build/documentation/` output. Documentation in this repository is
plain Markdown, read directly from `docs/`.
